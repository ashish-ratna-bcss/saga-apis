Two things that trip people up

Both come straight from the code, and both cause "why is nothing happening?"

Registering does not start collection

monitoring_enabled: true on POST /api/sources only sets a column. The collection job selects on both monitoring_enabled = true and access_status = 'MONITORING'.

  • A source left at PUBLIC_ACCESSIBLE with the flag on is never collected.
  • Only POST /api/sources/{id}/monitoring/start moves it to MONITORING.
  • That state exists in the live database today (source 7).

"Search" means two different things

Five endpoints query Telegram live; three read rows already collected. They never mix.

  • Live — /api/telegram/search/global, /api/sources/{id}/search, /api/telegram/channels/{id}/search. Every call hits Telegram.
  • Stored — /api/messages, /api/sources/{id}/messages. Free, unlimited, no rate-limit risk.
  • Live search persists nothing. The only writer is POST /api/telegram/search/results/save.

Access states gate everything

A source's status decides whether search, monitoring and backfill are allowed to run at all.
