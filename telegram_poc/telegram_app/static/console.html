Telegram session

GET /api/telegram/status — the real connection state. Everything that touches Telegram fails until this says authenticated.

Sign in

Three steps, in order. Only needed once — the session file is reused on every restart. The code hash is held in server memory, so don't restart the service between steps.

These are real Telegram login calls. Sending a code repeatedly will get the account rate-limited by Telegram.

Register a source

POST /api/sources — resolves the identifier and probes real access immediately. Accepts @username, a t.me link, an invite link, or a numeric id.

The flag alone does not start collection. A source is only collected once its status is MONITORING, which the Start monitoring button below sets.

Global search live

GET /api/telegram/search/global — hits Telegram on every call. Check method_used in the response: searchPosts is genuinely cross-channel, searchGlobal is scoped to this account.

Search inside one source live

GET /api/sources/{id}/search — only sources with verified access appear here.

Search an unregistered channel live

GET /api/telegram/channels/{id}/search — probes access afresh every call, so it costs two extra round trips. Register the channel if you'll query it more than once.

Stored messages local only

GET /api/messages — reads what has already been collected. No Telegram traffic, no rate limits. Keyword is a case-insensitive substring; there is no AND/OR syntax.

Find channels live

GET /api/telegram/channels/search — returns channels, not messages. The access status shown is a coarse hint, not the verified state.

Extract Telegram links from text live

POST /api/telegram/discovery/extract-links — read-only preview. Non-Telegram URLs are classified and discarded, never fetched. Capped at 20 probes per call.

Join by invite link changes membership

POST /api/telegram/invites/join — invite links only (t.me/+hash). For a plain username, register it and use Request access instead.

This makes the account actually join. Rapid repeated joins are the most common trigger of Telegram account restrictions.

Start a bot sends a message

POST /api/telegram/bots/{id}/start — sends exactly one /start and reads the reply. Only sources whose type is bot are listed.

Notifications local only

GET /api/notifications — access granted/rejected and collection errors. Polling is the only delivery mechanism; no webhook or websocket provider is registered.

Marking read does not persist. POST /api/notifications/{id}/read returns 200 but the change is rolled back — a known defect in the service, not in this console.

Raw request

Anything not covered above. The path is appended to the API base URL.
